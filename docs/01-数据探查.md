# 01 数据探查

> 数据集：淘宝用户行为（UserBehavior）
> 原始文件：`/home/atguigu/data/raw/UserBehavior.csv`（3.5 GB，另有同名 zip 906 MB）
> 探查方式：对 3.5 GB 文件做全量单遍 awk 扫描（非抽样），以及 20,000,000 行抽样做关联性检查
> 探查时间：2026-10-23

## 1. 字段与格式

| 字段 | 含义 | 类型 | 示例 |
|---|---|---|---|
| user_id | 用户 ID | 整数 | 1 |
| item_id | 商品 ID | 整数 | 2268318 |
| category_id | 类目 ID | 整数 | 2520377 |
| behavior_type | 行为类型 | 枚举 pv/cart/fav/buy | pv |
| timestamp | 事件时间戳（秒） | 整数 | 1511544070 |

- 逗号分隔，**无表头**，一行一个行为事件
- 字段数异常行：**0**
- 空字段行：**0**

## 3. 行为分布

| 行为 | 行数 | 占比 |
|---|---|---|
| pv（浏览） | 89,716,264 | 89.59% |

| fav（收藏） | 2,888,258 | 2.88% |

## 5. 数据质量问题（这些决定了 DWD 的清洗规则）

| 问题 | 实测 | 处理 |
|---|---|---|
| 时间戳越界 | 9 天主窗口之外的记录约 **55,576 行（0.055%）**，其中含**负值时间戳**（落在 1970 年之前） | 不丢弃，进 ODS `dt='invalid'` 分区留审计；DWD 只取合法分区 |
| 事件乱序 | 相对上一行时间回退的行 **988,155 行** | 不依赖文件顺序；分区一律由 `ts` 派生，DWD 排序用窗口函数 |
| 完全重复事件 | 20M 抽样中 **8 条**（推算全量约 40 条），即 user+item+behavior+ts 完全相同 | DWD 用 `row_number()` 去重（按天增量，代价可控） |
| 非法行为类型 | **0** | 仍保留白名单过滤作为防御 |
| 商品跨类目 | 20M 抽样中 **600 个商品**出现多个 category_id | 维表不能以 item_id 直接映射类目；取出现次数最多的类目为主类目，并打 `is_multi_category` 标记 |
| 类目 ID 为 0 | **0** | 无需特殊处理 |

## 6. 这份数据**不能**支撑的指标（重要边界）

数据只有行为流，没有金额、订单号、库存、渠道、优惠信息，因此以下指标**一律不做**，避免编造：

- GMV、销售额、客单价、ARPU
- 退款率、退货率、履约时长
- 渠道归因、投放 ROI
- 毛利、库存周转

对应地，本项目所有指标都是**行为类指标**（流量、转化、留存、复购、路径、集中度）。

## 7. 存储与计算规模预估

- ODS（TextFile 不压缩）：3.5 GB × 3 副本 ≈ 10.5 GB
- DWD（ORC + snappy，8 列）：预计 1.2~1.8 GB
- DWS/ADS（聚合后）：百 MB 级
- 单日处理量：约 1,000~1,400 万行，适合按天增量调度
